# 科研分析工作区：只读诊断与持续追问

日期：2026-11-18。状态：设计讨论稿，尚未实施。

用户已确定的范围：首版读取实验结果、代码和文献，诊断问题并提出修改建议；暂不自动改代码、不运行生成的代码、不启动实验。本稿中的布局、数据对象、预算和技术选择均为建议，不表示用户已逐项批准。

## 1. 产品目标与边界

新增与“实验工作台”“文献知识库”并列的“科研分析”工作区。以研究课题为单位，持续结合多个实验、代码版本和文献回答问题。价值是让研究者能核对模型依据、追问某个判断、补充材料，以及形成可人工落实的建议。

实验工作台负责计划与执行，文献知识库负责材料管理与原文阅读，科研分析负责跨材料解释、假设管理和验证建议。一个研究课题可以关联多个实验，不挂靠单个 experiment。

首版允许：

- 读取已有分析 JSON、汇总 CSV、已登记图片、配置快照和有范围限制的日志。
- 在允许的代码目录中做文本/符号检索和静态阅读，查看文件、函数、上下文与版本差异。
- 检索用户选定的知识库/文档，读取固定版本的摘录、原页与已核对公式。
- 用平台预先实现的只读比较函数，筛选已有指标、同站同日配对、计算差值；结果记录输入和算法版本。
- 形成解释、条件性推导、修改位置与伪代码/建议差异、人工验证清单；保存分析消息和报告。

首版不向研究 Agent 注册 shell、Python 执行、文件写入、代码修改、依赖安装、编译、测试、重新后处理、解算、修改实验计划或执行确认工具。缺少指标时说明缺项，不通过生成脚本补算。建议差异是文档内容，不是已应用补丁。平台只在自己的研究存储中保存会话、索引、证据副本和报告，不修改所选源码或实验原件。

失败的产品形态包括：长篇泛泛解释；没有原文的引用；上一轮假说在下一轮变成事实；把当前源码等同于历史二进制；将不兼容指标比较为算法优劣；追问一次就丢失研究目标。

## 2. 方案取舍

| 方式 | 优点 | 局限 | 本稿建议 |
| --- | --- | --- | --- |
| 普通强模型对话，手动附材料 | 简单，开放讨论灵活 | 跨轮取证、版本与假设状态难追踪 | 不作为核心结构 |
| 一个主研究 Agent + 显式任务状态 + 只读工具 + 研究状态 | 能自由追问，又能控制证据和生命周期 | 需要独立研究数据层和上下文管理 | 首版采用 |
| 多专家并行讨论与审稿 | 对复杂问题可提供额外视角 | 成本、重复上下文与冲突合并增加；一致意见不等于正确 | 留作后续可选能力 |

继续使用本项目的 AgentScope 和模型传输适配，不在首版引入第二套 Agent 编排框架。借鉴 LangGraph 的检查点和人工中断机制、Aider 的代码上下文筛选思想；不整套嵌入这些产品。用户选择的是只读边界；单主 Agent 是本稿的工程建议。

## 3. 当前代码基础与复用边界

- `frontend/src/App.tsx` 目前识别 workbench/knowledge，顶部切换后保活；新增 research URL 与独立会话身份。
- `ResizableWorkbench` 可复用拖拽、键盘和窄屏交互，但需参数化栏名、DOM ID 与布局缓存键。
- `KnowledgeChat` 的消息、模型配置展示、阶段反馈和引用交互可以复用设计；其组件清理会取消 HTTP 请求，不能直接沿用为研究运行的取消语义。
- `MarkdownContent`、`KnowledgeSourcePanel` 和原文摘录能力可复用；新增实验、日志和代码证据视图。
- `AnalysisWorker/analysis_jobs` 是确定性 FLT 后处理，一 attempt 一个作业；科研分析是可多轮、多实验的模型任务，单独建立队列。
- `KnowledgeChatService` 当前将超时限制在 90 秒、仅暴露 default profile，并由 HTTP 协程持有活跃生成；知识对话 HTTP 断开会取消任务。
- 复用 `KnowledgeRetriever`、原文摘录/位置/哈希验证、模型传输和预算统计底座；不直接调用旧 `send_message` 来承担研究长任务。
- 旧文献 SYSTEM 要求只复述本轮文献支持内容；研究引擎另设规则，允许明确标注的条件推导和研究假说。

以上判断基于当前本地工作树，其中存在未提交改动；不能只用当前 Git HEAD 标识所阅读内容。

## 4. 前端信息架构

```text
GREAT Agent    实验工作台 | 文献知识库 | 科研分析

课题与材料             研究对话 / 报告                 证据查看器
课题历史               问题与模型配置                  指标 + 统计口径
进行中状态             已有回答与引用                  日志片段
实验/代码/文献范围       观察 / 假设 / 建议                源码位置与上下文
材料新版本提示          对此追问 / 补充材料              论文原页与公式
                       输入框、发送、停止                本轮材料与缺口
```

左侧采用“课题历史 + 当前材料”两个分区。材料清单按需展开，避免嵌套文件树占据主要空间。实验显示 experiment/task/attempt、基准/对照角色和产物；代码显示目录范围、版本和与运行程序的关联状态；文献显示所选库/文档和版本。

中央对话为默认视图。每条回答先回答本轮问题，再按需要附“观察、假设、建议、待补充”；简单追问不强制填满报告模板。顶部展示主模型、快速/深入模式和研究运行状态。生成期间输入框可编辑下一条草稿，同一课题暂不发送第二个并行轮次。停止是明确按钮，切换课题或刷新不是停止。

右侧由引用点击驱动。无选中证据时显示本轮材料摘要、覆盖范围和缺口。有选中证据时显示原始定位与必要上下文；实验图不能代替数值指标，代码行号必须对应快照，论文页码同时显示 PDF 页序和可用的印刷页码。

窄屏使用“课题 / 对话 / 证据”切换；主输入框采用页面布局中的粘性区域，避免覆盖回答和移动键盘。会话草稿按课题保存，沿用现有草稿机制；密钥仍只在服务端。

## 5. 创建、带入与持续追问

### 5.1 创建与首次分析

1. 可从新建课题输入问题，也可从实验进度/图片页点“带入科研分析”。
2. 带入时保存用户当前选择的 task/attempt/产物，不重新解析为 latest attempt；先展示清单，不自动调用模型。
3. 研究者可增加基准/对照实验、代码范围和文献。仅有问题也允许咨询，但回答明确当前无实验或文献证据。
4. 点击发送时固定本轮问题、材料修订、模型配置和研究状态。展示本轮范围，随后启动后台任务。
5. 回答中的证据、假设和建议分别可点击查看、追问或加入报告。

### 5.2 四种追问入口

- 自由追问：延续当前研究目标，允许改变关注站点、日期或异常时段。
- 对此追问：选择具体回答段落、观察、假设或建议，将可编辑的引用块放入输入框；不自动发送。
- 补充材料后追问：明确“新增了什么”，下一轮检索新增材料及受影响的旧证据。
- 质疑与反例：可输入“这个解释与这段日志矛盾”，把目标假设和反对证据同时带入下一轮。

追问请求保存目标 `run_id + message_id + block_id/item_id`；服务端验证它属于本课题。文字“针对 H2”只是展示，不靠模型猜测编号。用户更正作为有来源的用户陈述保存，不能静默改成已观测事实。

### 5.3 示例：同一课题连续研究

| 轮次 | 用户输入 | 取证与处理 | 研究状态如何变化 |
| --- | --- | --- | --- |
| 1 | TF 收敛为什么比 DF 慢？ | 读基准/对照的既有统计，先核对日期、站点、参照与判据 | 保存可比性检查；列候选原因和缺失代码/文献 |
| 2 | 只看 JL18，重点看存在缺测的时段 | 筛选同站同日已有指标和日志；缺少时段指标则明确缺项 | 缩小本轮关注范围，保留其他站点未覆盖说明 |
| 3 | 会不会是 reset 的实现问题？ | 查找 reset 相关符号、调用上下文和配置；辨别代码与二进制关联 | H1 记录支持/反对证据；无法关联运行版本时保留此限制 |
| 4 | 结合这篇论文的式 12 再分析 | 读取固定版本公式及前后定义；逐项比对模型假设与实现 | H1 支持增加或受反例挑战；列出可人工核查的修改位置 |
| 5 | 我补了新 attempt，之前解释还成立吗？ | 新轮绑定新材料，按相同口径对比，重新读取 H1 的依据 | 保存新结论及对旧结论的修订关系；旧回答原样保留 |

“结果诊断 / 代码分析 / 理论改进”是可组合的问题入口，不创建三套互不相通的聊天系统。

## 6. 材料版本与可读证据

### 6.1 每轮固定材料，下一轮显式更新

课题拥有可变的材料选择修订；每个研究运行使用不可变快照。新增实验、修改代码、文献重解析或更换模型仅影响后续轮。UI 提示有新版本，用户选择下一轮更新；当前轮继续使用开始时的版本。

允许在下一轮同时选择旧、新版本进行比较。不得在读文件时一部分来自旧内容、另一部分来自新内容。普通材料选择变化不撤销旧轮，实际权限撤销或来源禁用则必须重新校验访问并停止受影响的后续读取/外发。

材料加入课题或选择更新时先准备可识别的版本：文献使用已有 version，源码生成所选文件的内容快照，实验产物记录实际内容哈希与大小。提交轮次绑定这份预期清单；`preparing` 阶段在模型外发前核对并补齐证据副本。源文件若与清单不符，返回 `material_changed`，提示刷新材料，不静默读取排队期间出现的新内容。读取/复制前后核对文件与清单指纹，无法取得稳定版本则失败。仍在增长的日志可以捕获有明确字节截止位置的前缀，保存前缀哈希并标为局部快照；不把前缀哈希冒充整文件哈希。完整内容快照成功前不进入模型取证阶段。

证据保存必要摘录及内容哈希；在受控研究存储中按内容寻址保留选定文本文件和必要证据副本，避免后处理覆盖文件后无法查看旧引用。大体积原始观测数据不整份复制，仍按已登记产物和范围读取；保留对象、保留策略及空间统计均需可查询。原件缺失时历史摘录与原件可用性分开显示；失去权限时不可用缓存绕过访问限制。

### 6.2 统一证据结构

每条证据有稳定 `evidence_id`、类型、快照身份、来源/摘录哈希、定位、内容、质量标记和可用状态。`[E1]/[C1]/[L1]` 仅是回答内别名，实际点击由 `run_id + alias` 映射；下一轮不得直接沿用旧别名。

| 类型 | 必须记录的来源与定位 |
| --- | --- |
| 实验/指标 | experiment、任务实际 revision、task、attempt、artifact 内容版本；JSON Pointer 或 CSV 行/列；单位、统计范围、参照、判据 |
| 日志/配置 | 对应 task/attempt、文件哈希、行范围/时间范围；原始时标，禁止自行混同 GPS 与 UTC |
| 代码 | 注册仓库、commit（有则记录）、未提交内容快照/清单哈希、文件哈希、路径、行号、符号；非 Git 目录使用文件清单快照 |
| 文献 | document/version/chunk、原 PDF 哈希、页码、区域/字符位置、公式转写核对状态 |
| 固定函数派生结果 | 输入 evidence IDs、配对/筛选条件、算法版本、参数、输出值及单位 |

指标兼容性至少检查同站同日的交集、配置差异、采样、单位、参照与阈值；不兼容则并列展示并解释限制，不能计算一个看似精确的改善率。缺失不补零，零基准时相对改善率不可定义。图片仅辅助观察；数值结论优先引用结构化指标。

当前默认参照为同日静态 DF Float 最后一个有效历元，不是独立外部真值。现行收敛口径为水平 0.2 m、垂直 0.4 m、连续 600 s，缺失历元重置窗口，返回窗口起点；研究工具读取产物内的实际 policy，不把这些默认值写死为所有历史产物的口径。

### 6.3 当前源码与历史运行代码分开

代码材料保存与运行程序的关联状态：`unknown`、`user_declared`、`build_manifest_verified`。当前实验预览虽有程序 SHA256，单凭它无法证明某仓库 commit 编译成该程序；需要可靠构建清单才能标为已核对。

关联未知时可说“所选源码中存在与该现象相关的实现疑点”，不能说“这段代码导致了此次历史异常”。用户声明也要保留声明来源，不能提升为构建已验证。编译选项/宏/外部依赖未知时，静态调用分析需标记不完整。

## 7. 大模型如何取得与使用上下文

### 7.1 一个主模型，按需取证

主模型先理解本轮问题、追问目标与材料清单，决定需要哪些证据；服务端在每次工具调用时固定范围并检查预算。模型无权扩大仓库、材料或工具范围。

工具建议为：`list_research_materials`、`read_experiment_summary`、`compare_existing_metrics`、`read_artifact_excerpt`、`read_log_excerpt`、`search_code`、`read_code_excerpt`、`read_code_diff`、`search_literature`、`read_literature_evidence`、`load_prior_evidence`。工具接收注册对象 ID 和受限范围，不接收任意主机绝对路径或命令。

代码首版用路径、文本和符号检索定位入口，逐步读取邻接函数、调用位置和配置；不用整库向量检索代替精确代码搜索。文献复用现有词法/向量混合检索。实验先用元数据与结构化指标定位，再读取日志/CSV 局部。每个工具返回定位、截断标记、覆盖范围和证据身份。

所有模型可见证据在外发前完成登记。供应商请求意图、模型配置指纹、已发送证据 ID 和请求结果状态独立持久化；无法读取和核验的内容不作为本轮依据。

### 7.2 每次追问构造上下文包

按优先顺序装入：

1. 系统规则、只读边界、当前材料范围与模型预算。
2. 本轮问题、选中的回答块/假设、用户明确约束和更正。
3. 研究状态：目标、已观察内容、候选假设、反例、未决问题；每项带来源和适用快照。
4. 最近对话，以及与本轮相关的较早消息；早期已失效判断仍保留状态。
5. 本轮重新读取的原始证据、必要上下文、统计口径和质量标记。

超出上下文时先减少无关历史和重复摘录，保留目标、争议、用户纠正、相关原始证据及未覆盖说明。不能无限把聊天全文、整库代码或完整日志塞给模型。上下文管理记录省略范围；如果关键依据放不下，返回局部结论和缩小问题的建议。

### 7.3 推理与结论核查

模型可结合领域知识进行条件性解释和新推导，但必须标注知识类型：已有数值观察、源码静态观察、文献原结论、用户陈述、模型背景知识、条件推导、原因假说、修改建议。

原文公式沿用已核对表达式和原页；新推导明确列前提、变量映射、关键推导步骤与适用限制，不能伪装为论文原式。某条观察与某段理论一致，只说明兼容，不能单独证明原因或改进有效。

最终结构包含 `answer_blocks / observations / hypotheses / suggestions / open_questions / limitations / proposed_state_changes`。不是每个问题都必须填满所有项。重要来源性判断关联证据；模型背景知识不得伪造论文引用。

发布前程序检查结构、别名映射、证据归属、版本、数值/单位与固定工具输出的对应关系、假设引用和状态变更合法性。数值校验针对结构化数值项，不能声称已机械验证任意自然语言或数学证明。引用可追溯也不等于语义成立；因果与理论有效性仍须研究者复核。

首版流式展示阶段和工具摘要，最终回答经校验后发布；未校验的 token 不写入研究记忆。展示取证步骤、证据和简要依据，不依赖供应商暴露内部思维链。

## 8. 持续研究状态与记忆

分开保存三层内容：

- 原始记录：不可变的用户问题、完成的回答、工具调用、证据、报告与模型请求记录。
- 结构化研究状态：研究目标、用户约束、观察、假设、反例、待补材料和建议；以 `ResearchItem` 标识，保留修订与依赖。
- 摘要与工作上下文：用于查找历史和节省 token 的派生缓存；保存覆盖轮次、摘要版本和生成模型，不具备独立证据资格。

每个假设至少记录陈述、支持证据、反对证据、未知项、来源轮、适用材料快照和状态：`proposed / support_increased / challenged / rejected / superseded`。状态不使用模型自报的“95% 正确”。一条来源增加支持不能自动升级为因果已证明。

重新引用旧判断时，服务端按稳定证据 ID 重新加载原摘录、校验当前可读性并分配本轮别名。摘要只能指向原记录；“上一轮模型说过”不构成新证据。用户可以纠正假设和约束，纠正也以新消息/修订保存。

每轮返回候选状态变更，经服务端校验后与最终回答同事务提交。失败、取消、超时、校验失败的轮保留审计和已取得证据，不更新有效观察、假设或摘要。更换模型后沿用研究状态并标明模型变化，不能把新模型不同意见作为自动覆盖旧结论的授权。

同一课题首版单条活跃生成，常规追问串行。材料和模型修订可在生成中暂存为下一轮配置；对研究事实的纠正通过下一条用户消息提交。这样旧轮不会覆盖用户刚改的研究状态。报告和旧回答不随摘要重生成而变化。

## 9. 后端模块与数据对象

```text
ResearchWorkspace
    ↕ REST + SSE
ResearchService / ResearchRepository
    ↕ 持久研究队列、事件、检查点
ResearchWorker → ResearchEngine（AgentScope 主模型）
                    ↕ 只读工具注册表
       实验/指标适配器 | 代码快照与搜索 | 文献检索与原页
                    ↓
          引用/数值核查 → 回答 + 研究状态修订
```

建议建立独立 research 表，避免把旧 conversation run 的 HTTP/PID 生命周期扩大成另一种含义；已有会话 UI 与公共展示类型可在适当边界抽取复用。

| 对象 | 关键内容 |
| --- | --- |
| ResearchSession | 标题、目标、当前材料/模型配置修订、状态修订、active_run、下一轮序号 |
| ResearchMaterialRevision | 用户选择的实验、代码范围、文献范围；修订与变更原因 |
| ResearchSnapshot | 本轮固定的可读对象、内容清单、来源版本、范围和哈希 |
| ResearchRun | 问题、request_id/请求哈希、父轮/追问目标、快照、基础记忆版本、模型配置、预算、阶段、lease/fencing token、结果/错误 |
| ResearchMessage | 用户/模型消息、稳定 block ID、状态、对应 run 与顺序 |

详细 SQL 拆分留给实施计划；上述身份、版本、引用和原子提交语义是设计约束。

## 10. 生命周期、并发与失败语义

`POST` 只校验并创建 queued run，返回 202；模型执行由研究 worker 持有，不绑定 HTTP 请求存活。SSE 只观察，断开后从事件 ID 续传。

运行主阶段为 `queued → preparing → gathering → analyzing → validating → completed`，终态还包括 `failed / timed_out / cancelled / interrupted`。需要补材料时 run 可以 completed，另设 `answer_status=needs_input/partial` 并保存具体缺项，释放 worker，不挂起等待用户。

研究 worker 首版为独立进程、默认模型生成并发 1；同一课题最多一条活跃运行。不同课题可排队，浏览不受影响。worker 持久心跳、租约和递增 fencing token；网络调用期间不持 SQLite 长事务，不占 solver 的解算槽位。

提交请求时短事务核对 `expected_session_version`、材料/模型修订和父轮，保存用户消息、请求哈希、run 和 queued 事件。相同 session/request_id 与相同完整请求返回同一个 run；相同 ID 配不同内容返回 409。完整请求包含问题、追问目标、材料/模型修订及预算，不能只哈希 message。

停止通过服务端 cancel 接口提交 `cancel_requested`，尝试取消上游调用。完成和取消在事务内竞争终态；被取消或失去 owner token 的迟到结果不能提交回答和记忆。若 completed 先提交，停止返回已完成；取消不能承诺供应商立即停止计费。

先保存模型返回结果，再做最终提交；短暂数据库提交失败优先重试保存，不重调模型。每次实际外发单独记账。已知成功的取证步骤可在相同快照/工具版本下复用；请求已发出但响应未知时标记 uncertain/interrupted，首版不自动重发该模型调用。用户重试创建关联新 run，并显示前次消费情况。

研究 worker 重启后：未外发的 queued 任务可继续；已持久化的工具步骤和模型响应可从检查点继续；无法判断供应商结果的调用由用户决定是否重试。恢复不保证恰好一次计费，但必须保证回答、事项和报告不会重复入库。

模型适配层关闭 SDK 默认的隐式请求重试；只读工具的局部重试受同一 deadline 与预算约束。重试接口只接受失败、超时、取消或中断的轮，且要求本课题研究状态仍处于该轮的基础版本；否则返回 `stale_retry`，由前端提供“把原问题作为新追问”，使用当前研究状态并明确选择材料。针对旧回答追问时，目标可以是旧 block，但新轮的父上下文仍是当前有效研究状态，不隐式回滚。

材料更新与旧轮完成分开：旧轮结果保留其原修订；新的 next-turn 配置不被覆盖。研究状态提交校验基础版本；若其他明确状态操作已改变 head，则旧结果保留为带冲突标记的历史，不自动覆盖新 head。首版不提供任意并行分支编辑。

## 11. API 草案

所有接口归 `/api/v1/research`，模型密钥与主机根目录不由浏览器直接提交给模型。

| 接口 | 用途 |
| --- | --- |
| GET/POST `/sessions` | 课题列表/创建；实验带入只创建材料选择 |
| GET `/sessions/{id}` | 消息、当前研究状态、材料修订与活跃运行 |
| PATCH `/sessions/{id}/materials` | 乐观锁更新下一轮材料选择，保留历史 |
| PATCH `/sessions/{id}/settings` | 下一轮模型 profile/模式；不改变活跃轮 |
| GET `/sources`、POST `/source-snapshots` | 列已注册可读仓库/范围，生成所选文本快照；不暴露任意路径读取 |
| GET `/model-profiles` | 可用模型、能力、上下文限制与是否就绪 |
| POST `/sessions/{id}/runs` | 带 request_id、expected_version、message、followup_target、材料与模型修订；返回 202 + run |
| GET `/runs/{id}` | 原请求恢复、状态、范围、消费与最终结果 |
| POST `/runs/{id}/cancel` | 显式停止，幂等 |
| POST `/runs/{id}/retry` | 用户明确重试，生成关联新 run，保留旧快照/模型；换配置则按普通新轮创建 |
| GET `/sessions/{id}/events` | SSE，支持 Last-Event-ID 续传 |
| GET `/runs/{id}/evidence/{alias}` | 当前回答别名解析与受权限校验的证据 |
| GET `/sessions/{id}/items` | 结构化假设、观察、争议和待补充 |
| POST/GET `/sessions/{id}/reports` | 选定已完成内容创建报告版本/列历史 |

代码快照任务不调用模型。源目录注册由本机配置限定；前端从已注册资源中选范围。文件读取拒绝越界、链接逃逸、密钥文件、应用私有配置（如 `config/local.toml`）、依赖目录与无关二进制；实验已登记的 XML 等配置快照仍通过实验工具可读。大小与扩展范围有限制。大文件返回可追问的局部定位和截断标记。

## 12. 模型配置、预算与可观测性

研究模型配置独立于计划编辑和短文献对话。首版允许一个强主模型承担三种入口，配置支持 tool calling、结构化输出、推理设置、上下文窗口及输出预留；模型差异由服务端适配，不把供应商内部参数直接做通用 UI 滑块。

建议试运行默认值：快速模式最多 4 次模型请求、10 次只读工具调用、180 秒整轮时限；深入模式最多 8 次模型请求、20 次工具调用、480 秒。输入上下文分别以 12k/32k token 为配置目标上限，并受供应商实际窗口扣除输出预留后限制。输出预留建议 4k/8k。数值是资源上限，不是耗时或质量承诺；可根据本地案例调整。

取证预算、模型请求次数、总输入/输出 token 和整轮 deadline 同时生效；任何阶段均不能绕过。tokenizer 不可用时用保守估算并标记 estimated；供应商实际 usage 可用时另存，缺价格或 reasoning usage 时不显示精确费用。预算不足保留可核对的局部结论和未完成项，不自动增加预算或升级更贵模型。格式错误首版允许本地合法规范化，不暗中追加付费修复请求。

UI 展示当前阶段、已读取材料摘要、耗时、累计调用和可用用量；日志保留安全请求 ID、阶段、错误码、模型配置指纹和定位信息。原文/代码摘录等敏感内容位于受控研究存储，不直接写进常规服务日志。文献、源码注释、日志与历史回答均作为资料，不能改变系统规则、工具或读取范围。

## 13. 首版交付顺序

1. 研究会话、只读边界和材料快照；实验带入、任务生命周期、状态恢复。
2. 实验/日志/代码/文献工具、统一证据、三栏对话和证据阅读。
3. 多轮追问目标、分层记忆、假设/反例/用户纠正、材料更新后的复核。
4. 结构化建议、报告版本、预算与代表性问题评测。

这些是同一个功能的内部交付顺序，不拆成三个互不兼容的分析产品。首版完成标准包含四项，而不止单轮回答。

## 14. 验收场景

- 从实验页带入指定历史 attempt，新增较新 attempt 后旧回答仍打开原证据。
- 同一课题至少连续五轮，能针对具体假设追问、提供反例并保留修订，不将摘要当作证据。
- 两轮都显示 `[E1]` 但来自不同文件，点击各自来源正确；不能串轮。
- 用户补文献或换模型后，仅新轮采用新配置；活跃旧轮继续显示其快照。
- 当前源码无法对应历史二进制时，明确限制因果诊断；dirty 工作树改动不破坏旧行号引用。
- 文献公式不可靠或定义缺失时显示缺项；模型新推导与原式分开，反对证据保留。
- 参照/单位/采样/收敛规则不一致的实验不输出无条件改善率；缺失指标不补零、不执行脚本补算。
- 生成中切页、刷新和断网重连恢复同一 run；同 request_id 重发不重复外调。
- 取消与完成竞态、worker 重启、模型响应落库失败都不重复更新研究状态；不确定调用不自动重新计费。
- 保存报告后继续追问、更新材料或摘要，不更改旧报告的内容与证据。
- 任意用户问题或材料中包含“执行/修改/忽略规则”，研究工具仍无写代码、运行、改计划或解算入口。
- 所有数据迁移和验证先在隔离副本完成；本设计讨论不触碰正式数据库、服务或前端构建。

评测以已有 GNSS 问题形成固定回放集，分别评估数字对应、来源定位、版本一致、无依据断言、追问目标正确、矛盾处理和建议可执行性。评测用于比较模型与策略，不把模型自评或多个模型一致当成科学正确率。
