# 文献阅读剩余缺口完善

用户已在复核报告后明确要求“将剩余缺口的问题开始完善实施”。本轮沿用已批准的科研聊天阅读方案及当前 codex 分支，继续实施，不重新启动方案审批。

## 范围与实现取舍

1. 修复公式卡的原页定位：来源选择可携带目标物理页；服务器重新核验引用后，只在该引用真实页集合中选择目标页。普通引用仍默认第一页；缺失/越界目标回退到合法页。覆盖多页引用、切换引用、异步核验和无效目标。
2. 扩展本地公式能力：不安装或下载重型 OCR，不启用外发图片。先使用现有 PDF 字形与布局提取可支持的编号公式，保守拒绝无法可靠转换的符号/结构；保留原页、来源 SHA、区域和机器提取标识。人工核对缓存优先。不把单条 Tao 公式或本地字符提取说成全部扫描公式 OCR。衍生 LaTeX 仍仅在本地公式卡呈现。
3. 完成正式接入：沿用 SQLite 迁移与 WorkerLock，先做数据库/runs/配置及前端旧版本备份，验证副本迁移，再升级正式库；前端先独立构建并验证后切换。启动脚本应消除“旧 dist 存在就永远不构建”和“旧数据库直接启动失败”的问题，给出健康检查及可定位日志，不任意结束已有进程。
4. 实际验收：启动正式本地页面，执行新发送→等待气泡→真实检索阶段→有来源回答→公式卡→原文页→中英翻译→真实剪贴板→刷新恢复及手机布局。记录真实通过/失败，保留旧验收资料与失败尝试。

保留本地取证、权限复验、缓存身份、撤权投影、请求/工具/时间上限及原件/索引不变约束。用户本轮授权正式迁移和本机页面切换；先前“本轮只校验、不切正式环境”不再适用。云端模型仅沿用原有问题和短证据文本请求；图片传输仍关闭。

## 可替代路线

重型通用视觉 OCR 会引入下载、运行资源和额外传输/模型配置，不用于本轮默认路径。继续只有人工录入不能改善其他可读数字 PDF 的公式获取。本轮采用保守本地提取并明确覆盖边界，后续扫描件可通过独立可选 OCR 适配器扩展。

## 验收标准

- 多页引用中的公式按钮打开公式所在页，且不会跳出已核验引用。
- 至少多种非硬编码公式由原 PDF 字形提取为可渲染 LaTeX；无法支持的输入不猜测；缓存恢复和来源变化保护通过。
- 正式配置对应数据库通过 runtime schema，保留历史记录；正式 dist 与新构建一致；本机健康接口与页面可访问。
- 相关自动测试、类型检查、lint、生产构建通过，真实新轮次与翻译复制有独立取证。
