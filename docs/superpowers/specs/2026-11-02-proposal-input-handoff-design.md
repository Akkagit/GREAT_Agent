# 接受提案后的输入检查与 XML 交接

用户于 2026-11-02 明确批准第三项方案并要求立即实现。第二项咨询/skill 路由及第一项模型性能不在本次范围。

接受成功先保存 revision，然后自动执行一次本地只读输入检查；原对话卡展示检查中、通过、缺失、网络失败或版本失效。通过后提供“生成 XML 并预览”，用户点击后沿用现有冻结、XML 快照及复核页。实际入队继续要求复核页的明确确认。本地检查不写 XML、不冻结、不创建任务或批准。

对话卡与底部门禁共用工作区状态、动作锁和处理函数。缺失项展示类别、日期、测站、路径及状态，可原地重试。检查失败仍然保留接受成功，不误报接受失败。

检查绑定接受返回的不可变 revision UUID 和 number；前后端均拒绝不匹配版本，旧响应在卸载、切换实验、创建新提案或新检查后不得更新工作区。XML prepare 仍保留后端 pending、revision、输入再次检查等门禁。生成失败后重新读取状态，因为后端可能已冻结计划。

人工检查入口、现有持久化提案恢复、取消、移动布局及 XML 最终确认保持有效。刷新不恢复过往“检查通过”；本次不新增会话存储或后台 Worker，不进行真实计算或付费模型请求。
