## P1 的最终行为

### 统一计划校验与默认 profile

`PlanValidationService` 重建 Pydantic schema，并统一检查日期展开、最终日期非空、测站/输出非空、并发策略与已登记 profile。创建实验、生成候选、接受和冻结都使用同一服务。瞬时输入文件存在性仍由预检与启动前复核负责。

`ProfileRegistry.from_settings` 将现有实际配置冻结为输入、程序和模板三项引用。当前注册 `local_default`、`great_local`、`pppflt_base`；适配器通过注册配置进行路径解析、预检、渲染及命令生成，未知 ID 不能静默沿用默认值。

实现：[统一验证](/F:/GREAT_Agent/backend/src/great_agent/services/plan_validation_service.py)、[profile](/F:/GREAT_Agent/backend/src/great_agent/capabilities/profiles.py)、[适配器](/F:/GREAT_Agent/backend/src/great_agent/adapters/great_pppflt.py)。

### 数据库原子调度配额

`claim_next` 先取得 SQLite 写锁，再检查全局 running 数量和任务所引用冻结 revision 的实验上限；占槽、创建 attempt、active attempt 和事件在同一事务提交。配额已满时不创建 attempt；可以领取其他未满额实验。完成、失败或终态取消释放槽位，请求取消但进程仍运行时继续占用。

真实 SQLite 独立 engine/线程测试覆盖最后一个全局/实验槽位竞争、锁等待、事件失败回滚和终态释放。缺少 concurrency 的旧测试记录按 1 处理。领取任务不授予执行权限，原有批准检查仍在 Worker 启动前执行。

实现：[领取事务](/F:/GREAT_Agent/backend/src/great_agent/db/repositories.py)、[Worker](/F:/GREAT_Agent/backend/src/great_agent/runtime/worker.py)、[竞争测试](/F:/GREAT_Agent/backend/tests/test_scheduler_quotas.py)。

### 持久提案与不可变基线

新 `plan_proposals` 保存候选 JSON/摘要、diff、原始 revision UUID、来源、派生关系、状态及接受结果。API 重建后可读取；接受请求重发返回原 revision，不再新增版本。接受在写事务中同时验证实验归属、基线编号/UUID、当前状态、内容摘要和领域规则。

手工卡片记录创建时的基线；编辑已登记提案必须带 `source_proposal_id` 并继承原基线。模型请求在 await 前捕获版本，迟到结果遇修订变化会冲突。客户端不能通过换 expected_revision 或编辑旧卡片将候选自动绑定最新版本。

P1 沿用每实验一个活动提案的工作台语义，新登记提案会把旧 pending 标为 superseded；未来多会话的提案归属在 P2 再细化。接受会使其余旧候选失效；拒绝同样持久化。

实现：[PlanService](/F:/GREAT_Agent/backend/src/great_agent/services/plan_service.py)、[API](/F:/GREAT_Agent/backend/src/great_agent/api/experiments.py)、[聊天基线](/F:/GREAT_Agent/backend/src/great_agent/services/chat_service.py)。

### 前后端共同保护待确认提案

刷新会恢复真实 pending 提案；恢复状态独立于本地卡片。聊天失败/取消、放弃替代草稿、旧 session 失效后重新查询；未知、查询中或查询失败时保持检查输入和 XML 门禁关闭。迟到查询不能覆盖新聊天结果、有效本地编辑或其他实验。

服务端冻结还在同一 `BEGIN IMMEDIATE` 事务检查 pending，以稳定的 `409 pending_proposal` 拒绝未处理候选。页面收到该错误会恢复卡片。该异常独立于 `PlanFrozenError`，不会被执行预览服务捕获后继续生成 XML。

冻结/提案创建竞争测试保证二者不能同时成功；执行预览 API 回归明确断言被拒绝时没有冻结、XML、preview 或 task。原有完整 XML 审阅和严格 confirmed=true 授权继续生效。

实现：[工作区](/F:/GREAT_Agent/frontend/src/pages/ExperimentWorkspace.tsx)、[前端 HTTP 合同](/F:/GREAT_Agent/frontend/src/api/client.ts)、[恢复回归](/F:/GREAT_Agent/frontend/src/tests/ExperimentWorkspace.test.tsx)、[API 门禁回归](/F:/GREAT_Agent/backend/tests/test_proposal_api.py)。

迁移 [0003_plan_proposals.py](/F:/GREAT_Agent/backend/alembic/versions/0003_plan_proposals.py) 接续 0002，只新增提案表/索引。兼容应用 create_all 已建立该表的情况，结构不兼容时拒绝覆盖。历史数据测试覆盖 0001 升级、已建表、待确认提案，以及实际 XML preview、日任务、执行授权逐行不变。

**本轮没有升级生产数据库、启动真实 GREAT 或修改 GNSS 输入。** 开发者采用临时数据库与 mock solver 验证。使用新版本前应按 README 停止 API/Worker、同时备份数据库和 runs，再执行 `uv run alembic upgrade head`。前端已重新构建，已有浏览器须刷新；旧手工请求缺少 base_revision_id 会返回 422。

原版本的进程内提案和未保存浏览器草稿不能追溯恢复。P1 不保存完整聊天记录；后续 P2 才建立 conversation/message/AgentRun。
