日期：2026-10-22。项目目录：`F:\GREAT_Agent`。实施依据为同日执行确认计划和用户批准的三页式 UI 原型。本轮修改了正式 `frontend/src` 并完成生产构建，不再只是独立 HTML 草图。

## 已接通的链路

接受提案 → 检查输入 → 生成 XML → 执行复核 → 勾选并明确确认 → 入队解算 → 运行监控。

- 全局导航与本地历史实验侧栏；规划、执行复核、监控三页支持查询参数和浏览器前进/后退。
- 预览展示真实逐日 XML 全文、程序绝对路径及 SHA256、模板身份、命令与准确参数数组、完整输入检查报告、工作目录、输出目录和当前后处理行为。
- 生成预览只冻结计划和准备隔离快照，不创建待执行任务。未接受/未保存的修改阻止检查和生成旧计划。
- 确认请求必须携带预览 ID、revision 和严格 JSON `true`；默认 30 分钟过期。确认后排队不会因时限失去授权，但启动前仍重新检查身份。
- SQLite 事务序列化并发确认，逐任务、逐 attempt 授权唯一；确认重发幂等。API 和独立 Worker 重启不会丢失授权。
- Worker 执行审核过的 XML 字节，不重新渲染；程序、模板、XML 或输入身份改变会阻止启动。
- 失败/中断重试必须先复核下一 attempt；旧 `/run` 无请求体、旧 `/retry`、CLI `smoke` 和脚本 `-Execute` 都不能绕过。
- 停止通过 SQLite 投递到独立 Worker，同时取消等待任务。运行监控刷新已选日志和产物；自动跟随当前 attempt，手动选中的历史 attempt 保持不变。

## 独立复核与本轮取舍

按执行计划进行了独立、只读的新上下文代码复核；未发现 Critical。Important 问题为“选择 pending 任务后不发现新 attempt / 重试时仍显示旧 attempt”，已用两个前端失败测试复现并修复，完整前端 27 项通过。

本轮决定与代价：

1. 在唯一正式目录原地实施，保留所有既有脏工作区改动，不新建 worktree、不自动提交/推送；因此交付仍是待用户审阅的未提交改动。
2. 使用后续批准的三页原型作为布局依据，执行复核独立成页；这是对早期计划中内嵌区描述的更新，不改变执行门禁。
3. 两项已知 GLM 配置/总超时测试维持单独待办，不删测试或冒称全绿；模型连接优化未在本轮扩展实现。
4. 为使监控链路真实可用，修复跨进程停止请求和日志刷新；增加了少量 SQLite 取消检查及客户端刷新开销。
5. JSON 输出类型列表固定按名称排序，解决重读时顺序波动；只改变序列化次序，不改历史源文件和解算语义。
6. 迁移兼容 API 已自动建表的情况，验证列和主键后保留已有表；不做破坏性重建。
7. 保留本轮进度与备份目录直到人工提交，避免未提交记录丢失；只增加少量忽略的本地文件。
8. 不声称重新验收真实解算数值、GLM 行为，或抵御恶意本机进程在身份检查与启动间的文件竞争；本轮只验证既定的前置和启动前校验设计。
